# Data-source scouting for new pre-registered tests

Scouted 2026-11-12. Every "download test" below was run from the shell with `curl` (User-Agent
`sift-research <contact>`) or the Apify REST API; samples are in `/tmp/sift_samples/` (not committed). No repo code was
changed, no data committed. The sealed holdout (2025+) was not touched: only schema and history depth were inspected.

Point-in-time (PIT) rule used here: a source is PIT-clean if every record carries a publication or filing timestamp that
lets a strategy enter at the **next open** after that timestamp with no look-ahead.

## Recommendation: pull these three first

1. **FINRA short-sale volume (Reg SHO daily, per venue, 2016+) plus bi-monthly short interest (2017-12+).** Daily
   cross-sectional signal on exactly the stocks already in the store, a published-by-18:00 ET rule that makes next-open
   entry clean, and decades-old academic motivation (short-seller informativeness). Short-volume ratio and days-to-cover
   fit the existing 5-min/daily test harness. The short-volume ratio is known to be noisy (market makers), so register a
   simple pre-specified grid and compare with the market-adjusted check. Short interest history starts late 2017, still
   enough for the 2019-2024 test years. Needs a new `scripts/fetch_finra.py` in the house style (resumable, per-file
   skip, filter to universe symbols, write parquet).
2. **EDGAR event filings already in `data/edgar`: 13D (activist stakes), 13G/A jumps, Form 144 (insider intent to sell)
   and 8-K item codes beyond 2.02.** Zero new download for the ~408 issuers, second-level timestamps, large event counts
   (Form 144: 20,579; 13G/A: 51,578; 8-K items 1.01/5.02/2.05/8.01). Natural sequel to the closed insider-buying test
   (Form 144 is the sell side). Watch the Dec 2024 form-type rename (`SCHEDULE 13D/G`) and the Feb 2024 deadline change.
   NT 10-K is too sparse in this universe (80 rows) to test.
3. **S&P 500 additions and deletions, with true announcement dates from the S&P press releases.** About 25 changes a year,
   clean timestamp once the announcement (about 17:15 ET) is taken from the press release rather than Wikipedia's effective
   date, and an event class that has not been tested here. Sample is small (about 150 events in 2019-2024), so
   pre-register the single hypothesis (announcement-open to effective-date drift) and one grid. Fallback if the
   announcement dating costs too much effort: **House Clerk PTRs (9a)**, free and official but needing PDF parsing, and
   weakened by the 30 to 45 day filing lag and by the negative result of the closed political-posts test.

Cheap extras if a fourth is wanted: FOMC/CPI/NFP calendar (an hour of work, SPY/sector ETF event-window test, no
surprise values), Wikimedia pageviews attention, and the Nasdaq threshold-list diff.

## Caveats found along the way

- `.env` line 3 is not a `KEY=VALUE` line; `. ./.env` prints a "command not found" for it under zsh. Harmless for the
  keys, but worth cleaning. The Apify key was only read inside shell commands and never printed or written.
- FINRA historical file headers were rewritten in 2021, so only FINRA's published 18:00 ET rule, not file metadata,
  supports the PIT claim for 2016-2020 short volume.
- Apify run outputs expire after 7 days; save any data you want to keep.
- None of these sources was used on holdout-period (2025+) returns. Pull the files, then let the existing
  `config.HOLDOUT_START` guard refuse 2025+ in the analysis scripts, as for insider and political data.
